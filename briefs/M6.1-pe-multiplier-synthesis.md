# Brief: M6.1, NVFP4 PE multiplier: measure the implementation options, then build the winner

Follow `AGENT_LOOP.md`. Context: `docs/M6-design-debates.md` (D1, D2) and `docs/M3-scope.md` (the arithmetic).

**Goal**:
- **Phase A**: implement equivalent NVFP4 PE variants, prove them equivalent, and measure them with logic synthesis.
- **Phase B**: build the winner in Chisel (Chisel 6.7.0, matching Chipyard 1.14) with an exhaustive test, and confirm the Chisel-generated Verilog synthesizes as well as the hand version.

No changes to `~/chipyard`, `~/chipyard-mx` or `~/MxGen`, which are read-only here.

## The unit under test (identical interface for every variant)
`nvfp4_pe_<variant>`, purely combinational:
- inputs: `a0,a1,w0,w1` (4-bit E2M1 codes: sign, e[1:0], m), and `c00,c01,c10,c11` (13-bit signed column partial sums in)
- outputs: `d_ij = c_ij + P(a_i, w_j)` (13-bit signed), where `P` is the exact product of the **doubled** E2M1 values (magnitudes {0,1,2,3,4,6,8,12}, product range −144..144)
- the **golden model** is `refmodel/vectors/e2m1_pairs.json` (256 pairs). The doubled-value convention must match it; check that first.

Also build a **bare multiplier** version of each variant (`mul_<variant>`: `a,w` → 9-bit signed product), so both views get measured.

## Variants (Phase A)
| ID | Variant | Notes |
|---|---|---|
| V1 | Full LUT | `case({a,w})` with 256 entries giving the signed product |
| V2 | Magnitude LUT + sign | 64-entry case on `{a[2:0],w[2:0]}` giving an 8-bit magnitude; sign = `a[3]^w[3]`; negate to two's complement, then add |
| V3 | Decode + generic `*` | decode each to an int 0..12, signed `*`, then add |
| V4 | Structured shift-mux | decode to `(m'∈{1,3}, k)` per the D1 table; magnitude = `mux{1,3,9}(m'_a,m'_b) << (k_a+k_b)`; negate, then add |
| V5 | V4 + sign folded into the adder | no negation: `d = c + (s ? ~mag : mag) + s`, with s as the adder carry-in. Zero handled so −0 adds 0 |
| V6 | V5 + shared decode | each of a0, a1, w0, w1 decoded **once** and reused across the 2×2 products (V1–V5 decode per product) |

Write them as plain Verilog-2005 in `hw/pe_variants/`. Each variant's PE module must instantiate or compute 4 products the way that variant naturally would.

## Tools
Install `yosys` and `iverilog` from conda-forge into a **new** env `~/miniforge3/envs/eda` (`conda create -n eda -c conda-forge yosys iverilog`). No sudo. Record the versions. If yosys isn't available from conda-forge, report BLOCKED with alternatives; don't build it from source.

## Steps
| # | Step | Check |
|---|------|-------|
| 1 | Create the eda env | `yosys -V && iverilog -V` |
| 2 | Write V1–V6 (mul + pe) and a generated exhaustive iverilog testbench: all 256 (a,w) for `mul_*`, and for `pe_*` all 65,536 (a0,a1,w0,w1) combos × a few c values (0, +max-144, −max+144, random) | every variant: 0 mismatches vs the golden JSON. The testbench reads the JSON-derived hex. |
| 3 | Formal equivalence: for each variant vs V1, build a Yosys miter (`miter -equiv -flatten -make_assert` + `sat -verify -prove-asserts -show-ports`) on both `mul_*` and `pe_*` | every proof passes. Also do a negative control: deliberately break one product in a scratch copy of V4, and the proof must FAIL. |
| 4 | Synthesis metrics, per module (mul and pe), with a fixed script: `read_verilog; synth -flatten -top X; abc -g AND; stat` (AIG AND count) and a separate `synth; abc -g cmos2; stat` (generic gate count), plus logic depth via `abc -g AND` then `ltp -noff` | a table in `hw/pe_variants/RESULTS.md`: variant × {mul, pe} × {AIG ANDs, gates, depth} |
| 5 | **Decision rule** (fixed in advance; don't change it): winner = the smallest **PE-level AIG AND count**. If within 5% of the best, prefer the smaller depth, then the more readable structure. Write the decision + numbers in RESULTS.md. | the decision is stated with numbers |
| 6 | Phase B: implement the winner in Chisel as a small standalone project in `hw/nvfp4pe/`: `NvFp4Mul` (lane) and `NvFp4PE` (2×2, 13-bit column add), with mill or sbt pinned to Chisel 6.7.0. If an ivy/coursier cache from `~/chipyard-mx` is reusable, reuse it. Java comes from `~/chipyard-mx/.conda-env`, read-only use. | `NvFp4PE` elaborates to SystemVerilog |
| 7 | Exhaustive Chisel test with ChiselSim (`chisel3.simulator`, Verilator backend): all 256 lane pairs vs the golden JSON, plus a 65,536-combo PE sweep at c=0 and spot checks at the 13-bit bounds | 0 mismatches. Negative control: break one product, see a failure, restore. |
| 8 | Run the Chisel-generated Verilog through the step-4 script, and formally prove it equivalent to V1 | equivalent; AIG count within 10% of the hand-written winner (if not, explain why, e.g. Chisel structure, and whether a rewrite fixes it) |

**Done when**: steps 1–8 pass, with evidence in `logs/m6.1.steps`, `hw/pe_variants/RESULTS.md` holding the table and decision, and one dated PROGRESS.md session-log bullet. Make one commit at the end, prefix `M6.1:`.
