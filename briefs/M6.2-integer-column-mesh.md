# Brief: M6.2, exact integer column accumulation (NVFP4 mesh)

Follow `AGENT_LOOP.md`. Context: `docs/M6-design-debates.md` (D1 and D2 are DECIDED), `hw/nvfp4pe/` (the V6 PE in Chisel, verified in M6.1), `hw/pe_variants/RESULTS.md`.

**Decisions this builds on**
- D1: PE = V6, meaning shift-mux + sign folded into the adder carry-in + shared decode across the 2×2 PE (`NvFp4PE`).
- D2: partial sums flowing down a weight-stationary column are exact **13-bit signed integers per lane**.

**Goal**: two phases. **Phase A** must finish before Phase B starts; Phase B is a later brief, after coordinator review.
- **Phase A1, standalone mesh.** In `hw/nvfp4pe/`, build `NvFp4Mesh`: a DIM×DIM (default 16) weight-stationary array of `NvFp4PE` with 13-bit integer column sums, verified against the reference model.
- **Phase A2, integration plan, read-only on the MX base.** Write `docs/M6.2-integration-plan.md` explaining exactly how `NvFp4Mesh` (or `NvFp4PE`) would replace or sit beside the MX mesh in `~/chipyard-mx` Gemmini @ 266c593f, without breaking MX modes.

**Limits**
- Write only to `C:\Users\braed\gemmini-nvfp4`. `~/chipyard-mx`, `~/chipyard` and `~/MxGen` are read-only. Use `git show` / `grep` / `sed -n` to read them.

## Phase A2: integration plan contents
`docs/M6.2-integration-plan.md` must cover:
- **Option analysis.** At least: (i) a new NVFP4 mode inside the existing `mac_mx`/`MxFloat` path; (ii) a separate `NvFp4Mesh` instantiated beside the MX mesh and muxed by format at the ExecuteController; (iii) a config-time swap, giving an NVFP4-only build. For each: files touched (file:line), effect on MX modes, area, and Spike-model impact.
- **The mesh-to-accumulator boundary.** What the MX `AccumulatorMem` scaling path expects today (BF16 lanes), and what NVFP4 will deliver (13-bit int lanes). This feeds M6.3.
- **A recommendation**, plus any **new design decisions** the integration raises. List them as open questions. Don't decide them.

**Done when**: A1 steps 1–5 pass, with evidence in `logs/m6.2.steps`, and the plan doc exists. Add one dated PROGRESS.md session-log bullet; don't tick anything.

**Known risks**
- The MX mesh may skew and de-skew inputs (MeshWithDelays), so match its timing model, or document clearly where `NvFp4Mesh` differs.
- 13-bit bounds: one block's max |sum| is 2304 per lane. The tests must hit both extremes.
