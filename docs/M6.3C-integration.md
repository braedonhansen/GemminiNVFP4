Store path: the loop's BF16-mode spad store already walks `acc_write_w / spad_w` beats (8 for a 1024-bit FP32 chunk), one 128-bit entry (4 FP32) per spad row, so no `MxRequantizer`/DMA change was needed. An output row of 32 columns lands in 8 consecutive spad rows, row-major; software copies spad rows to DRAM with ordinary mvouts (as the M5 test does). A direct accumulator->DRAM FP32 store is NOT done: `StreamWriter` is limited to 64 B per request (`dma_maxbytes`) and a chunk is 128 B (open item).

Tensor scale: software computes `factor = (tA*tB)*0.25f` in float32 and passes it as the `acc_scale` argument of `gemmini_extended_config_st` before the loop (the loop's stores use the StoreController registers). Note `ACC_SCALE_IDENTITY` is bit pattern 0 = 0.0f: the NVFP4 config multiplies by whatever is configured, so software must always set a real factor (1.0f for none).
