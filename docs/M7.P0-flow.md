# M7.P0: power-flow preparation for stock INT8 Gemmini (Genus 25.1 + Joules 25.1, FreePDK45)

Status: **prepared and checked locally, not yet run on the server.** Nothing here has touched the USC server.
Run it with the two commands printed by `logs/m7p-ssh-cmd.sh int8-stock-a`.

## What the job is
Design: stock INT8 Gemmini, `~/chipyard` (Chipyard 1.14.0 `0acc1e1d`, Gemmini upstream `8c3f9923`, unmodified), `GemminiRocketConfig`
(DIM=16, scratchpad 256 KiB in 4 banks, accumulator 64 KiB in 2 banks). Top module `Gemmini` only; Rocket and the uncore are not in the job.

Job directory (`~/nvfp4-logs/m7p/jobs/int8-stock-a.tar.gz`, 115 MiB; MANIFEST holds sha256 of all 145 files):

### SRAM macros (black boxes in synthesis, no power in this job)
All six sit under `Gemmini.spad`. `mem_1_ext` (8192x64) is not under Gemmini (it is Rocket/periphery), so it is not in the job.

| Instance (under `Gemmini`) | Macro | Depth x width | Ports |
|---|---|---|---|
| `spad.spad_mems_0.mem.mem_ext` ... `spad_mems_3` (4) | `mem_ext` | 4096 x 128 | 1 RW, 16-bit write mask (mask_gran 8) |
| `spad.acc_mems_0.mem.mem.mem_0_ext`, `acc_mems_1` (2) | `mem_0_ext` | 512 x 512 | 1 R + 1 W, 64-bit mask |

4 x 64 KiB = 256 KiB scratchpad and 2 x 32 KiB = 64 KiB accumulator, matching the config. Their access energy is a P2 item (macro liberty
power or an access-count model). The waveform does contain their port signals (`RW0_*`, `R0_*`/`W0_*`) under `gemmini.spad`, which is what
P2 needs for access counts.

## Workload and window (P0.3)
- Test: `hw/tests/m7p_int8_64x64x512.c`. `tiled_matmul_auto` (stock weight-stationary path), 64x64x512, INT8 inputs, **full-width INT32 output**
  (same choice as M7.A; the requantised INT8 output is the C3 variant for later). Operands are xorshift32 pseudo-random full-range int8 so the
  data are not trivial.
- Check in the test: Freivalds test over all 4096 outputs (exact int64) + 4 complete rows recomputed directly. Fails if nothing was compared.
  Variants: `-DM7P_FULL_REF` (all 4096 outputs directly), `-DM7P_CORRUPT` (flips one output bit, must fail).
- Sim: out-of-tree Verilator 5.022 build in `~/nvfp4-logs/m7p/sim` (nothing under `~/chipyard` was written). It uses the tree's own
  generated Verilog and the same Verilator options as `make -n debug`, with two changes: a patched copy of `TestDriver.v`
  (`hw/power/sim/patch_testdriver.py` + `m7p_monitor.vh`: window control and a Gemmini monitor) and `hw/power/sim/m7p.vlt`, which restricts
  tracing to the Gemmini instance (`tracing_off -scope "*"` then `tracing_on -scope "TestDriver...gemmini*" -levels 99`).
- Two passes of the same binary, which is deterministic (both end at the same cycle):
  1. no dump; the monitor prints every RoCC command fire and every `io_busy` edge with the cycle number;
  2. same run with `+m7p-start/+m7p-end`: `$dumpvars` at the window start, `$finish` at the window end.
  This Verilator version ignores `$dumpon/$dumpoff` (tested on a toy; a first attempt with them dumped the whole run, 1.6 GB, and was discarded), so the window is made this way.
- Window, in **Gemmini clock cycles** (the tile clock is half the TestDriver clock): first RoCC command after the kernel marker at cycle
  **472,969** to the last `io_busy` falling edge (after the last mvout and the fence) at **487,268**: **14,300 cycles**, 11 RoCC commands
  (the loop-matmul configuration and loop commands; the unroller expands them inside Gemmini).
- VCD facts (`act/vcdcheck.txt`): 42,123 signals, 23,427,084 value changes, 60,061 timestamps, 1,975 scopes, every signal under
  `TOP.TestDriver.testHarness.chiptop0.system.tile_prci_domain.element_reset_domain_rockettile.gemmini`, nothing outside it.
- **Time rescale.** The simulated Gemmini clock is 2000 ps; the SDC clock is 5000 ps. `m7p-vcdscale.py` multiplies every timestamp by 5000/2000
  (checked: the Gemmini `clock` signal then has period 5000 ps, same 23,427,084 changes), so the toggle rates Joules sees are those of the
  synthesis clock. Dynamic energy is independent of this; leakage energy and average power are not, which is why it matters.

## Clock choice: 5.0 ns (200 MHz)
This is an estimate, not a measurement; the first run's `reports/timing.rpt` is the first real data.
- The metric is energy at one fixed clock for every design, so the value has to be the same for all five designs and only has to be
  achievable by all of them. The slowest datapath in the set decides it: the stock FP32 PE (hardfloat multiply-add in one stage, DIM=4),
  then the NVFP4 FP32 adder pipeline and the MX BF16 accumulator.
- OSU FreePDK45 `gscl45nm` is a small cell set (few drive strengths, no sizing tricks) and the flow is synthesis only (no P&R, no clock tree), so a
  fast target mainly makes the tool upsize cells and distorts area and power. The INT8 PE (8x8 multiply + 32-bit add in a cycle) should close at
  well under 5 ns; the FP32 hardfloat path is the uncertain one.
- If INT8 closes with large positive slack at 5 ns while a later design fails, change the clock **for all designs together** and rerun INT8.
  Do not tune per design. `CLK_NS=<x> logs/m7p-pack.sh <job>` rebuilds the job (it rescales the VCD to the new period).
- The same VCD supports energy = average power x window time at the chosen clock: 14,300 cycles x 5 ns = 71.5 us.

## Scope mapping (VCD to synthesised design)
- VCD: `TOP.TestDriver.testHarness.chiptop0.system.tile_prci_domain.element_reset_domain_rockettile.gemmini` is the instance of module `Gemmini`.
  Verilator adds the `TOP` root; `joules_int8.tcl` uses `DUT=TestDriver/testHarness/.../gemmini` (without `TOP`) as `-dut_instance`.
- The synthesised top is module `Gemmini`, so VCD name `gemmini.X` corresponds to netlist `Gemmini/X`. RTL signal names are firtool names; Genus
  names registers `<name>_reg`, `<name>_reg[i]`, which is why the Genus database (`read_db`) is the preferred Joules input.
- Hierarchy groups for the power report (instance paths below `Gemmini`): mesh = `ex_controller/mesh/mesh`; scratchpad banks = `spad/spad_mems_0..3`
  (logic around the macros); accumulator = `spad/acc_mems_0..1` + `spad/acc_scale_unit`; DMA = `spad/reader`, `spad/writer`, `spad/xbar`, `spad/buffer*`, `tlb`;
  controllers = `load_controller`, `store_controller`, `ex_controller` (minus the mesh), `reservation_station`, `mod` (LoopConv), `mod_1` (LoopMatmul), the command queues;
  other = the rest. The Joules script writes one report per listed instance plus `-by_hierarchy` reports; summing into groups is done after the first run, when the report format is known.

## Commands to verify on the first run
Everything marked `VERIFY` in the two scripts was written from memory of the Genus/Joules command references; the 25.1 docs
(`/tools/cadence/DDI251/GENUS251/doc`, `JSTUDIO251`) exist only on the server. The scripts parse as Tcl and their control flow is exercised
against a mock shell (`logs/m7p-tclcheck.sh`: normal path, wrong macro count and empty VCD both fail), but no command has been run in the real tool.

Genus (`genus_int8.tcl`):
1. `set_db / .init_lib_search_path`, `.init_hdl_search_path`, `.hdl_language sv`, `.information_level`: attribute names and the value `sv`.
2. `set_db / .hdl_verilog_defines {SYNTHESIS}`: define syntax (Gemmini.sv guards sim-only init code with `ifndef SYNTHESIS`). Wrapped in `catch`.
3. `set_db / .auto_ungroup none`: needed to keep per-block area; values none|both|area|delay.
4. `read_libs` (vs `set_db library`), `read_hdl -sv <list>` (the file list is expanded in Tcl, not passed with `-f`).
5. `elaborate Gemmini`, `set_db / .current_design`, `check_design -unresolved`.
6. Macro handling: `get_db hinsts -if ".module.name == mem_ext"` (the object/attribute names), and the `.preserve` / `.blackbox` / `.dont_touch` settings on the stubs (all in `catch`; the script **exits with M7P-FAIL if it does not find exactly 6 macro instances**).
7. `get_db ports -if ".base_name == clock"`, `report_clocks`.
8. Reports: `report_area -depth`, `report_timing -max_paths`, `report_hierarchy`, `report_qor`, `report_gates`, `report_power -depth` (some versions use `-levels`).
9. Outputs: `write_hdl` (may need `-mapped`), `write_sdc`, `write_db -common -all_root_attributes -to_file`, `write_design -innovus` (optional).
10. `genus -no_gui -batch -files <tcl> -log <name>` (the course checks used `-no_gui -batch -execute`).

Joules (`joules_int8.tcl`):
1. `read_libs`, `read_db <genus db>` vs `read_netlist` + `elaborate` + `read_sdc` (the script falls back to the netlist route if no db exists).
2. `read_stimulus -file -format vcd -dut_instance -start -end`: option names, the time units of `-start/-end` (the script passes VCD ps), and whether the dut path wants `/` or `.` separators.
3. `compute_power -mode time_based` (vs `average`/`vectorbased`).
4. `report_power -unit mW -outfile`, `-by_hierarchy -levels N`, and the per-instance form (`-hierarchy <inst>`, else `-root <inst>`).
5. Annotation coverage: three candidate commands are tried in turn (`report_annotation`, `report_activity_annotation`, `report_activity -annotation`), plus a flop count through `get_db insts -if ".is_flop == true"` with a `.activity_annotated` attribute. **If none works, read the coverage lines that `read_stimulus` prints in `reports/joules.out` and fix the command name.** The brief's required number (fraction of flops annotated) must come out of the first run.
6. `joules -batch -files` invocation.

`run.csh` is tcsh and could not be syntax-checked locally (tcsh is not installed in WSL). Things to check on a first look: `source ~/setup_ee477_ee577a_v2602.csh` works from a non-interactive `tcsh run.csh`; `gunzip -k` exists; the backtick-in-`if` conditions.

## Expected failure modes on the first server run, and what to change
| Symptom | Likely cause | Change |
|---|---|---|
| `M7P-FAIL library file missing` | the OSU path differs or the file is read-protected | `ls -l /tools/PDK/NCSU45PDK/FreePDK45/osu_soc/lib/files/`; set `LIB_PATH` in `run.csh` (several files allowed). The lib may be split into several corners: use the typical one |
| Warnings about missing cells / "dont_use", `unmapped` flops, many `LBR-` messages | a cell family absent from `gscl45nm.lib` (e.g. no flop with async reset, no enable flop) | read `reports/genus.out` for the first `CDFG`/`MAP`/`LBR` error; Gemmini needs plain D flops with sync reset, which the lib has. If the lib lacks a needed function, `set_db / .dont_use` is not the fix: report it |
| Genus errors in `read_hdl` on SystemVerilog | `-sv` / `.hdl_language` wrong, or a construct Genus rejects in firtool output (`final`, `$fwrite` with `PRINTF_COND`, `automatic`, packed structs) | try `set_db / .hdl_language v2001` with `-sv` per file; the firtool code that is not under `ifndef SYNTHESIS` is the place to look; a source patch is out of scope for P0 (needs the user) |
| `M7P-FAIL expected 6 macro instances, found 0` | the `get_db hinsts ... .module.name` form is wrong, or the empty stubs were deleted at elaboration | `get_db hinsts` and `get_db modules` interactively; alternatives: `.module.base_name`, `-if {.module == module:Gemmini/mem_ext}`; or `get_db insts` filter on `.base_cell`. If the stubs vanished, build the macros as library cells instead: write a small `.lib` with `mem_ext`/`mem_0_ext` (area/pin data only), `read_libs` it, and drop `sram_stubs.sv` (P2 needs such a file anyway, with power) |
| Black box has undriven/removed outputs, or the stub gets mapped to flops | stubs are empty modules, not recognised as black boxes | the `.blackbox`/`.preserve`/`.dont_touch` lines are the knobs; as a last resort leave the stubs out of the file list and let Genus black-box unresolved references (set `hdl_error_on_blackbox` accordingly) and check port widths in `check_design` |
| Area report has no hierarchy | `auto_ungroup none` ignored | check `get_db / .auto_ungroup`; `set_db [get_db modules *] .ungroup_ok false` per module |
| Timing fails badly (WNS far negative) | 5 ns too aggressive for the lib | read `reports/timing.rpt` first; per the clock rule, change it for all designs, not just this one |
| Genus runs hours / OOM | no P&R stage but 16x16 MAC array + queues is large | `NCPU`; the server's job limits; note the run time in PROGRESS |
| `M7P-FAIL read_stimulus` or "no signals matched", annotation near 0% | VCD scope mismatch: wrong `-dut_instance`, or name mapping of registers (`_reg`) | try `.` separators, with and without the `TestDriver` prefix, and the `TOP` prefix; use `read_db` rather than `read_netlist`; check the Joules log for the first unmatched-name message. The VCD scope chain is exactly the one under "Scope mapping" above |
| Joules complains the VCD has no clock or a clock-period mismatch | rescaled time vs SDC | the VCD `clock` period is 5000 ps = `CLK_NS`; if `CLK_NS` is changed, repack (the pack script rescales) |
| Read of `kernel.vcd` very slow / memory heavy | 540 MB, 42k signals, 23 M changes | run Joules with only the needed sub-scopes (`-dut_instance` deeper), or shrink the window with `-start/-end`; this is expected to take minutes, not hours |
| `SRAM` power missing from the total | by design (black boxes) | list them for P2; nothing to fix |

## Limits to keep in mind
- Synthesis only: no wires, no clock tree. Absolute power is optimistic; relative comparison at one clock is the goal (M7 plan, stage 3).
- RTL VCD annotated onto a synthesised netlist: flop and port activity is annotated, combinational activity is propagated, so internal-net activity is an estimate.
- The vectorless `report_power` from Genus is a sanity number only (it uses default input activity).
- Rocket is not in the measurement; the test's setup and check code run on Rocket outside the window.
- The workload writes INT32 outputs. The INT8 requantised output (C3) is not measured here.
